## Incidents in detail

### CRITICAL tier (1–2)

**1. LiteLLM AI-gateway PyPI supply-chain compromise (TeamPCP) — terabytes of credentials from 2,500+ orgs — Mar 2026.** On 24 Mar 2026 (10:39 UTC, ~40 min live) the threat group TeamPCP published malicious LiteLLM PyPI releases 1.82.7/1.82.8 (and Telnyx 4.87.1/4.87.2 on 27 Mar) after stealing the maintainer's publishing credentials via a prior compromise of the Trivy scanner in LiteLLM's CI. LiteLLM is a widely used open-source LLM gateway (~3.4M downloads/day). The multi-stage payload harvested env vars, SSH keys, cloud/Kubernetes/Docker credentials, DB creds, crypto wallets and CI/CD secrets (exfil to models.litellm.cloud / checkmarx.zone), installed a systemd backdoor, and could create privileged Kubernetes pods for lateral movement. CloudSEK/Hudson Rock analysed a ~195TB leaked dump and assessed credentials exposed from 2,500+ organisations (incl. Microsoft, AWS, Cisco, Samsung, Salesforce). AI recruiter Mercor confirmed it was 'one of thousands of companies' affected; Lapsus$ separately claimed Mercor data.
*VERIS: Confirmed · Observed **Critical**, Potential **Critical** (confidence High). Stolen cloud/CI-CD credentials at this scale enable follow-on intrusions across thousands of organisations' production and pipelines.*
**Sources:** [VCDB #23174](https://github.com/vz-risk/VCDB/issues/23174), [VCDB #24173](https://github.com/vz-risk/VCDB/issues/24173) · **Reporting:** [LiteLLM](https://docs.litellm.ai/blog/security-update-march-2026), [Datadog Security Labs](https://securitylabs.datadoghq.com/articles/litellm-compromised-pypi-teampcp-supply-chain-campaign/), [TechCrunch](https://techcrunch.com/2026/03/31/mercor-says-it-was-hit-by-cyberattack-tied-to-compromise-of-open-source-litellm-project/)
**Validated CVEs:** *primary:* [CVE-2026-33634](https://www.cve.org/CVERecord?id=CVE-2026-33634) · 1 added vs. original record · Original record had no CVE; the malicious LiteLLM releases are covered by CVE-2026-33634.

**2. Mexican government mega-breach via jailbroken Claude Code — Dec 2025.** A solo attacker jailbroke Claude with bug-bounty framing and a 1,084-line 'hacking playbook', then used Claude Code as planner and autonomous executor against Mexican federal/state/municipal systems — breaching 10+ agencies and a financial institution, running 5,317 AI-executed commands across 34 sessions (~75% of all command execution). Impact: ~150 GB / ~195 million records (names, RFC/CURP IDs, voter data, employee credentials). Among the largest confirmed real-world AI-driven data thefts.
*VERIS: Confirmed · Observed **Critical**, Potential **Critical** (confidence Medium). National-scale identity/voter/credential data in criminal hands enables large-scale fraud and follow-on intrusion; among the largest AI-driven thefts on record.*
**Sources:** `ClaudeCode_DeepResearch_ai_incidents_2026.md` · **Reporting:** [SoCRadar](https://socradar.io/blog/mexican-government-breach-claude-chatgpt/), [UpGuard](https://www.upguard.com/news/sat-data-breach-2026-03-02)
**Validated CVEs:** none identified · Jailbroken Claude Code used as attacker; SOCRadar/UpGuard sources name no CVE (20+ unspecified vulns, credential abuse).


### HIGH tier (3–24)

**3. Autonomous offensive agent (CodeWall) breached McKinsey's Lilli AI platform via SQLi in 2 hours — Feb 2026.** Security firm CodeWall pointed its autonomous offensive AI agent at McKinsey's internal AI platform 'Lilli' (43,000+ employees) with no credentials or human-in-the-loop. Within ~2 hours the agent mapped 200+ API endpoints (22 unauthenticated), found one that concatenated JSON *keys* (not values) into SQL, exploited a blind SQL injection that standard scanners missed, and gained full read/write to the production database: 46.5M plaintext chat messages, 728,000 files, 57,000 user accounts, 95 system-prompt/model configs and 3.68M RAG chunks; it also chained an IDOR to read individual search histories. Write access to the prompt-storage table meant system prompts could have been silently rewritten. McKinsey patched within hours of disclosure (test end Feb, disclosed Mar 1) and said a third-party forensics firm found no evidence client data was accessed by any unauthorised third party.
*VERIS: Confirmed · Observed **High**, Potential **Critical** (confidence High). Write access to the system-prompt table enabled silent, log-free poisoning of advice delivered to 43,000 consultants (poisoned strategy/financial output, guardrail removal, data exfiltration via responses) plus mass exfiltration of highly confidential strategy/M&A data.*
**Sources:** [AIID 1412](https://incidentdatabase.ai/cite/1412) · **Reporting:** [codewall.ai](https://codewall.ai/blog/how-we-hacked-mckinseys-ai-platform), [The Register](https://www.theregister.com/2026/03/09/mckinsey_ai_chatbot_hacked/), [AIID](https://incidentdatabase.ai/cite/1412)
**Validated CVEs:** none identified · Blind SQL injection + IDOR in a bespoke internal platform (McKinsey Lilli); no CVE assigned.

**4. Novo Nordisk breach — clinical-trial data AND internal AI model assets stolen (FulcrumSec) — Mar 2026.** Novo Nordisk disclosed (11 Jun 2026) that attackers accessed internal IT systems and copied non-public data including pseudonymised clinical-trial patient data, healthcare-provider contacts, other proprietary data AND internal AI model assets. FulcrumSec claimed entry via a GitHub access token in March 2026, ~2+ months dwell, and 1.3TB exfiltrated; Novo refused a reported $25M ransom and the group said it was exploring private sales. The AI dimension is that AI model assets were among the loot — theft OF AI rather than AI as the cause. Already encoded in VCDB (validated).
*VERIS: Confirmed · Observed **High**, Potential **Critical** (confidence High). Public sale/leak of clinical-trial patient data + proprietary drug R&D and AI model assets would be a large-scale, irreversible confidentiality and competitive/IP loss.*
**Sources:** [VCDB #23360](https://github.com/vz-risk/VCDB/issues/23360), [VCDB #23372](https://github.com/vz-risk/VCDB/issues/23372), [VCDB validated/FE704346…](https://github.com/vz-risk/VCDB/blob/master/data/json/validated/FE704346-BF9A-4435-927B-16A7ECF24C43.json) · **Reporting:** [novonordisk.com](https://www.novonordisk.com/news-and-media/latest-news/incident-update.html), [SecurityWeek](https://www.securityweek.com/ozempic-maker-novo-nordisk-says-hackers-breached-it-systems/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/pharmaceutical-giant-novo-nordisk-discloses-security-breach/)

## Method & caveats

- **Scope & union.** 99 incidents = 35 (`AISEC-2026-*`, from the AIID + VCDB registers) + 64 (`MRG-2026-*`, from the four deep-research reports), with no overlap. Contents are identical to the two source JSONs; only each incident's original-source citations were normalised.
- **Original sources.** Register incidents cite the AIID export (`incidentdatabase.ai_20260824_ai_incidents_2026.xlsx`) and/or the VERIS Community Database (`vz-risk/VCDB`) — the latter at the exact `data/json/{validated,submitted}/<uuid>.json` record or the `issues/<n>` intake. Report incidents cite `ChatGPT`/`ClaudeCode`/`Grok`_DeepResearch_ai_incidents_2026.md. The **Reporting** links are the primary vendor/news/CVE sources from each record.
- **Coding.** Each incident carries a standard VERIS record (Actor/Action/Asset/Attribute, CIA, graded disclosure, scope, timeline, confidence) plus a separate report layer (AI role/component/mechanism, observed & potential severity, CWE/CVE with mapping basis). Where VERIS has no native concept (model extraction, prompt injection, autonomous agent action) the nearest valid coding is used and the AI meaning is carried in the report layer.
- **Ranking.** By **observed** severity, potential as tiebreaker — a report-specific ordinal rubric (Critical > High > Medium > Low > Negligible), **not** CVSS, the ChatGPT report's AIRIS, or the CC report's blended tier. Vulnerability-discovery / coordinated-disclosure PoC items sit at Negligible/Low observed and High/Critical potential.
- **Non-software-security rows.** Five MIT/VCDB register items are `security_incident = False positive` (privacy/likeness/governance harms, not asset compromises); ten conventional VCDB breaches with no AI component are flagged as such. Both are retained for register completeness, each with an AI-involvement note.
- **CVE validation (2026-08-26).** Every CVE ID in the original records was resolved against CVE.org/NVD and checked against the incident description; CISA KEV, the GitHub Advisory Database and each incident's primary sources were searched for omitted CVEs. The per-incident **Validated CVEs** line (and the `validated_cve` / `validated_cve_details` attributes in the JSON, `validated_cve` column in the CSV) carries the corrected list, grouped by relation (*exploited*, *exploited-unconfirmed*, *attempted*, *toolkit*, *primary*, *discovered*, *related*), with removed IDs and their reasons. Original title/summary text was left untouched, so a title may still cite an ID that the validation line removes or re-attributes.
- **Granularity note.** The Anthropic July-2026 cyber-evaluation incident (`AISEC-2026-033`) is coded as one incident under its single disclosure/root cause, though the ChatGPT report enumerated its three sub-incidents separately.
