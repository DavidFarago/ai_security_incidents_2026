**DR-2026-064. 'Ghostcommit' — a prompt injection hidden in a PNG makes AI coding agents commit a repository's .env secrets past AI code reviewers — Jun 2026.** Researchers of the University of Missouri-Kansas City's ASSET Research Group (Sudipta Chattopadhyay, Murali Ediga) built 'Ghostcommit', a pull request whose malicious instruction is a picture: text-based AI code reviewers (Cursor Bugbot, CodeRabbit) never open the PNG and wave the change through, and a coding agent that later reads the image follows it and writes the repository's whole .env into the source code as a list of numbers. Across ten runs each, Cursor and Google's Antigravity coding tool followed the image and leaked the .env under Sonnet, Gemini and GPT-5.5, among others; Claude Code, running the same Sonnet weights, refused. 'All testing used a seeded, non-production credential in repositories we control; no real secrets were used or exposed.' The findings were disclosed to the affected vendors, and a proof of concept was published on GitHub (ASSET Research Group, June 2026; BleepingComputer, 11 Jul 2026). The source item of this record also reports Mozilla 0DIN's malicious-repository demonstration (DR-2026-104) and the malicious npm package mouse5212-super-formatter (DR-2026-105).
*VERIS: Near miss · Observed **Negligible**, Potential **High** (confidence High). The demonstrated path: a pull request that passes AI review and later makes a coding agent commit the repository's .env secrets in encoded form. **DR-2026-104. Mozilla 0DIN: a repository without malicious code makes Claude Code open a reverse shell through indirect prompt injection — Jun 2026.** Researchers of Mozilla's 0DIN (Andre Hall, Miller Engelbrecht) showed that a GitHub repository without a single line of malicious code can compromise a developer's machine through Claude Code. In their proof of concept, the project fails on first use with a setup error; Claude Code runs the suggested setup script to fix it; the script fetches a DNS TXT record whose value decodes to a reverse shell. The shell runs 'as the developer's own user, exposing credentials, API keys, and allowing persistence'. The payload is never in the repository, so code review, static scanners and the agent itself cannot see it: 'Claude Code never decided to open a shell. It decided to fix an error.' (0DIN, 25 Jun 2026; Help Net Security, 29 Jun 2026). No source reports use against a victim, a vendor fix, a CVE or a bounty.
*VERIS: Near miss · Observed **Negligible**, Potential **High** (confidence High). The demonstrated path ends in a reverse shell with the developer's rights, 'exposing credentials, API keys, and allowing persistence'. It needs a developer who lets the agent set up a malicious repository: a compromise of developers' machines one at a time, not a mass compromise.*
